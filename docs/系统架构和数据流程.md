## 1. 整体架构

### 1.1 系统分层

```
┌─────────────────────────────────────────────────────────────┐
│                    前端层 (Vue 3 SPA)                        │
│  - 用户界面  - 状态管理  - 路由管理  - API调用              │
└────────────────────────┬────────────────────────────────────┘
                         │ HTTP/HTTPS (REST API)
                         │ WebSocket (实时推送)
┌────────────────────────▼────────────────────────────────────┐
│                  后端 API 层 (Go + Gin)                      │
│  - REST API  - WebSocket  - 认证鉴权  - 请求验证            │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│                   业务逻辑层 (Go)                            │
│  - 任务管理  - 策略管理  - 网卡管理  - 系统监控             │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│              流量生成引擎 (Traffic Engine)                   │
│  - Config Workers  - Packet Workers  - Output Workers       │
│  - Ring Buffer  - Rate Limiter  - Protocol Planners        │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│                   数据持久层                                 │
│  - SQLite/MySQL (任务/策略)  - 内存缓存 (实时数据)          │
└─────────────────────────────────────────────────────────────┘
```

## 2. 前后端交互方式

### 2.1 交互模式：**直接调用后端 REST API**

前端通过 Axios 直接调用后端 REST API，**没有中间层或网关**。

```
前端 (Vue) ──HTTP──> 后端 (Go Gin) ──> 业务逻辑 ──> 数据库
     │                    │
     └────WebSocket───────┘ (实时推送)
```

### 2.2 API 基础配置

**前端 API 配置** (`web/src/api/index.ts`):
```typescript
const request = axios.create({
  baseURL: '/api/v1',        // API 基础路径
  timeout: 30000,            // 30秒超时
  headers: {
    'Content-Type': 'application/json'
  }
})
```

**后端路由配置** (`internal/api/rest/server.go`):
```go
v1 := s.router.Group("/api/v1")
{
    tasks := v1.Group("/tasks")
    system := v1.Group("/system")
    interfaces := v1.Group("/interfaces")
    strategies := v1.Group("/strategies")
    settings := v1.Group("/settings")
    auth := v1.Group("/auth")
}
```

### 2.3 请求拦截器

**请求拦截器** (添加认证 Token):
```typescript
request.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})
```

**响应拦截器** (统一错误处理):
```typescript
request.interceptors.response.use(
  (response) => {
    if (data.code !== 0) {
      ElMessage.error(data.message)
      return Promise.reject(new Error(data.message))
    }
    return data
  },
  (error) => {
    // 401: 跳转登录
    // 403: 权限不足
    // 404: 资源不存在
    // 500: 服务器错误
  }
)
```

## 4. 状态管理 (Pinia Store)

### 4.1 Task Store

```typescript
// stores/task.ts
export const useTaskStore = defineStore('task', () => {
  // State
  const tasks = ref<Task[]>([])
  const currentTask = ref<Task | null>(null)
  const loading = ref(false)
  
  // Actions
  const fetchTasks = async () => {
    const response = await taskApi.list()
    tasks.value = response.tasks
  }
  
  const createNewTask = async (data) => {
    const task = await taskApi.create(data)
    tasks.value.unshift(task)
  }
  
  return { tasks, currentTask, loading, fetchTasks, createNewTask }
})
```

**使用场景**:
- 跨组件共享任务数据
- 避免重复 API 调用
- 统一状态管理

## 7. 业务流程符合性分析

### 7.1 ✅ 符合后端业务流程

1. **任务生命周期管理**
   - 创建 → 启动 → 运行 → 停止 → 完成/失败
   - 前端状态与后端 Engine 状态一致

2. **流量生成流程**
   - 前端提交任务 → 后端验证 → Engine 处理 → Workers 生成流量
   - 符合后端 Pipeline 架构

3. **数据持久化**
   - 任务/策略存储在数据库
   - 实时数据在内存中
   - 符合后端存储设计

### 7.2 ✅ 前后端交互合理

1. **直接 REST API 调用**
   - 简单高效，无中间层
   - 适合中小型系统

2. **统一错误处理**
   - 响应拦截器统一处理错误
   - 用户体验一致

3. **认证机制**
   - JWT Token 认证
   - 请求拦截器自动添加 Token

### 7.3 ⚠️ 可优化点

1. **API 响应缓存**
   - 当前每次都请求后端
   - 可以添加前端缓存减少请求

2. **批量操作**
   - 当前单个任务操作
   - 可以添加批量启动/停止

3. **错误重试**
   - 当前失败直接提示
   - 可以添加自动重试机制

## 8. 总结

### 8.1 架构特点

- **前后端分离**: Vue SPA + Go REST API
- **直接调用**: 无中间层，简单高效
- **实时推送**: WebSocket 实现实时数据更新
- **状态管理**: Pinia 统一管理前端状态
- **类型安全**: TypeScript + Go 强类型

### 8.2 数据流向

```
用户操作 → Vue组件 → Pinia Store → Axios → 后端API → 业务逻辑 → Engine → 数据库
                                                ↓
                                          WebSocket Hub
                                                ↓
                                          实时推送更新
```

✅ **完全符合后端业务流程**
- 任务管理流程完整
- 状态转换正确
