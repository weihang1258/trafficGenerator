## 3. R5 新问题（2 项）

### M-SRV6-R5-1：S13 HexDump 行标算术错误（0x7f0/0x800 应为 0x810/0x820）

**位置**：§6.13 S13（1136-1144 行）

**描述**：
- S13：127 段 SRH = 8 + 16×127 = 2040 字节
- IPv6 头：offset 0-39（40 字节）
- SRH：offset 40-2079（2040 字节）
- UDP 起始：offset 2080 = **0x820**
- List[126]（第一段）起始：40 + 8 + 126×16 = **2064 = 0x810**

文档 HexDump：
```
07f0  fc 00 ... s1 01      <- List[126]=第一段
0800  <UDP 头 + payload>
```

**问题**：0x7f0 = 2032，但 List[126] 应在 2064（0x810）；0x800 = 2048，但 UDP 应在 2080（0x820）。行标整体偏移 -32 字节（2 行）。

**影响**：HexDump 是 BYT 断言的字节基准，但 S13 为边界值场景（127 段），实现者主要验证 Hdr Ext Len=0xFE（254），不依赖行标做断言；行标错误仅影响人工阅读。

**修复建议**：行标改为：
```
0810  fc 00 ... s1 01      <- List[126]=第一段
...
0820  <UDP 头 + payload>
```

### L-SRV6-R5-1：S4/S14 HMAC TLV config value 字节数不足（32B vs 38B）

**位置**：§6.4 S4（769-778 行）、§6.14 S14（1157-1166 行）

**描述**：
- S4 config：`"value": "0000000100000000000000000000000000000000000000000000000000000000"`（64 字符 = 32 字节）
- S14 config：`"value": "8000000100000000000000000000000000000000000000000000000000000000"`（64 字符 = 32 字节）
- RFC 8754 §2.1.2 HMAC TLV Value = D+RES(2B) + KeyID(4B) + HMAC(32B) = **38 字节**
- 正确 value 应为 76 字符：`000000000001` + `00`×32（S4）或 `800000000001` + `00`×32（S14）

**影响**：HexDump 显示正确的 40 字节 TLV（Type+Length+Value），字段构成描述的 38 字节 Length 也正确，但 config 示例值不足。实现者若直接复制 config 的 value 字段，会得到 32B HMAC 而非 32B，导致 TLV Length 字段（0x26 = 38）与实际 Value 长度（32）不符。

**修复建议**：config value 改为完整 76 字符（38 字节），或添加注释说明"value 示意，实际需 38 字节"。
