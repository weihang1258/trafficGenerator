## 1. 项目概述

### 1.1 项目背景

现有Python版本流量生成器存在以下问题：
- 性能瓶颈：受GIL限制，吞吐量约100K pps
- 内存占用大：多进程架构，进程间通信开销高
- 扩展性差：单文件2336行，维护困难
- 部署复杂：依赖Python环境

### 1.2 重构目标

**核心目标**：
1. **性能提升10倍+**：吞吐量达到 1M+ pps
2. **模块化架构**：清晰分层，便于扩展和维护
3. **协议插件化**：方便添加新协议（DNS、ICMP、ARP等）
4. **生产级质量**：完善的监控、日志、错误处理
5. **易于部署**：单二进制文件，跨平台支持
6. **标准化接口**：支持REST API、gRPC、MCP规范
7. **可视化管理**：提供Web管理界面

### 1.3 技术选型

| 组件 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 编程语言 | Go | 1.21+ | 高性能、并发优秀 |
| Web框架 | Gin | 1.9+ | 高性能HTTP框架 |
| RPC框架 | gRPC | 1.60+ | 高性能RPC |
| 报文处理 | gopacket | 1.1+ | 成熟的报文库 |
| 配置管理 | Viper | 1.18+ | 灵活的配置 |

| UI组件库 | Element Plus | 2.5+ | 企业级组件 |
| 图表库 | ECharts | 5.4+ | 数据可视化 |

### 2.3 并发模型

**Goroutine池设计**：

```go
// 配置生成池（可配置数量）
for i := 0; i < numConfigWorkers; i++ {
    go configWorker(taskChan, configChan)
}

// 报文构造池（可配置数量）
for i := 0; i < numPacketWorkers; i++ {
    go packetWorker(configChan, packetChan, rateLimiters)
}

// 采集器（单goroutine）
go collector(packetChan, buffer)

// 监控器（单goroutine）
go metricsCollector()
```

**Channel设计**：

```go
taskChan   := make(chan Task, 1000)        // 任务队列
configChan := make(chan PacketConfig, 2000) // 配置队列
packetChan := make(chan []byte, 2000)       // 报文队列
```

## 3. 功能需求

### 3.1 核心功能

#### 3.1.1 协议支持

**第一阶段（MVP）**：
- ✅ TCP：完整握手、数据传输、挥手
- ✅ UDP：请求/响应模式
- ✅ HTTP/1.1：Keep-Alive多事务

**第二阶段**：
- ✅ DNS：查询/响应
- ✅ ICMP：Echo Request/Reply
- ✅ ARP：请求/响应

**第三阶段**：
- ✅ HTTPS：TLS握手
- ✅ HTTP/2：多路复用
- ✅ QUIC：UDP上的HTTP/3

#### 3.1.2 参数生成策略

所有参数支持以下策略：

| 策略 | 说明 | 示例 |
|------|------|------|
| fixed | 固定值 | `{"strategy": "fixed", "value": 80}` |
| increment | 递增循环 | `{"strategy": "increment", "start": 1, "end": 100, "step": 1}` |
| random | 随机生成 | `{"strategy": "random", "min": 1024, "max": 65535, "seed": 42}` |
| pattern | 模式递增 | `{"strategy": "pattern", "template": "user{n}", "start": 1, "end": 1000}` |
| list | 列表选择 | `{"strategy": "list", "values": ["GET", "POST", "PUT"]}` |
| weighted | 加权随机 | `{"strategy": "weighted", "values": [{"value": "GET", "weight": 70}, {"value": "POST", "weight": 30}]}` |

#### 3.1.3 速率控制

- **按类别限速**：每个流量类别独立速率控制
- **全局限速**：总体流量上限
- **动态调整**：运行时动态修改速率
- **突发控制**：令牌桶算法，支持突发流量

#### 3.1.4 批量混合生成

支持多种协议并发生成：

```json
{
  "classes": [
    {
      "id": "tcp_web",
      "type": "tcp",
      "bps": "200M",
      "flows": {"count": 1000}
    },
    {
      "id": "dns_query",
      "type": "dns",
      "bps": "50M",
      "flows": {"count": 500}
    }
  ],
  "global": {
    "total_flows": 2000,
    "duration": "60s"
  }
}
```

## 5. MCP规范支持

### 5.1 MCP协议概述

**Model Context Protocol (MCP)** 是一个开放协议，用于标准化应用程序如何向LLM提供上下文。

**为什么支持MCP？**
- ✅ 标准化接口，便于AI工具集成
- ✅ 支持Claude、其他AI助手直接调用
- ✅ 提供工具（Tools）和资源（Resources）
- ✅ 实时上下文更新

#### 6.4.3 WebSocket实时更新

```typescript
// composables/useWebSocket.ts
export function useWebSocket(taskId: string) {
  const ws = ref<WebSocket | null>(null)
  const status = ref<TaskStatus | null>(null)
  
  const connect = () => {
    ws.value = new WebSocket(`ws://localhost:8080/ws/tasks/${taskId}`)
    
    ws.value.onmessage = (event) => {
      const data = JSON.parse(event.data)
      if (data.type === 'status_update') {
        status.value = data.data
      }
    }
  }
  
  onMounted(connect)
  onUnmounted(() => ws.value?.close())
  
  return { status }
}
```

## 7. 数据结构设计

### 7.1 核心数据结构

#### 7.1.1 任务结构

```go
// Task 任务
type Task struct {
    ID          string    `json:"id"`
    Name        string    `json:"name"`
    Description string    `json:"description"`
    Spec        TaskSpec  `json:"spec"`
    Status      string    `json:"status"` // created, running, paused, completed, failed
    Progress    float64   `json:"progress"`
    Stats       TaskStats `json:"stats"`
    CreatedAt   time.Time `json:"created_at"`
    StartedAt   *time.Time `json:"started_at,omitempty"`
    CompletedAt *time.Time `json:"completed_at,omitempty"`
}

// TaskSpec 任务规范
type TaskSpec struct {
    Classes []TrafficClass `json:"classes"`
    Flows   FlowConfig     `json:"flows"`
    Global  GlobalConfig   `json:"global"`
}

// TrafficClass 流量类别
type TrafficClass struct {
    ID     string                 `json:"id"`
    Type   string                 `json:"type"` // tcp, udp, http, dns
    BPS    string                 `json:"bps"`  // 速率限制
    Config map[string]interface{} `json:"config"`
}
```

#### 7.1.2 策略结构

```go
// Strategy 策略
type Strategy struct {
    ID          string                 `json:"id"`
    Name        string                 `json:"name"`
    Protocol    string                 `json:"protocol"`
    Description string                 `json:"description"`
    Config      map[string]interface{} `json:"config"`
    UsageCount  int                    `json:"usage_count"`
    CreatedAt   time.Time              `json:"created_at"`
    UpdatedAt   time.Time              `json:"updated_at"`
}
```

#### 7.1.3 报文配置结构

```go
// PacketConfig 报文配置
type PacketConfig struct {
    FlowID      string    `json:"flow_id"`
    PacketIndex uint64    `json:"packet_index"`
    ClassID     string    `json:"class_id"`
    Direction   string    `json:"direction"` // up, down
    L2          L2Config  `json:"l2"`
    L3          L3Config  `json:"l3"`
    L4          L4Config  `json:"l4"`
    Payload     []byte    `json:"payload"`
}
```
