# JTT905（JT/T 905-2014）代码设计

> 版本：v2.0.1（2026-10-01，层链迁移后的 as-built 设计契约）
> 范围：JTT905 TCP/10700 单连接 ISU 会话；旧合集 Part C/D 的拆分说明已作废，不再作为本版依据。
> 机器真相：`trafficgen/test/protocol_pcap/cases/jtt905.json`（13 例，9 正/4 负）。

## 1. 范围与实现边界

JTT905 采用 TCP 长连接、7E 定界、7D 转义和 XOR 校验。当前生成面覆盖签到 `0x0B03`、心跳 `0x0002`、签退 `0x0B04`、中心通用应答 `0x8001`、ISU 通用应答 `0x0001` 及签到中的位置基本块。除这 5 种 procedure 外的标准消息族（参数、文本、电话、车辆控制、图像音频、订单扩展等）没有生成器入口，列为缺口 `G-JTT905-1`，不能写成已支持。

线格式依据 SmallChi/JT905 README 与 `JT905_0x0B03.cs`、`JT905_0x0B04.cs`、`JT905_0x0001.cs` 金向量交叉核对：消息头 12B（MsgId 2、DataLength 2、ISU BCD 6、MsgNum 2）；DataLength 是纯消息体长度，不含版本/加密/分包位；校验对未转义的 MsgId 至消息体末字节求 XOR，再转义头、体、校验并加 0x7E 首尾。

按 CORE §3.14，单 TCP 流对 `sessions[]`/`driven_by` 作有理由豁免：JTT905 规范没有独立控制/数据副流，因此不存在可关联的数据流；但同连接多轮、异常结束、长保活仍需覆盖或立项。当前 cases 使用严格 `layers: [ip, jtt905]`，地址住 `ip`，业务住 `jtt905`；默认目的端口 10700 由策略映射处理，未在顶层写旧端口字段。

| 上行/下行 | Result 0 | Result 1 | Result 2 | Result 3 |
|---|---|---|---|---|
| 0x0B03→0x8001 | T1/T6 | T14 | T14 | G-JTT905-4（当前 planner 拒绝） |
| 0x0002→0x8001 | T4 | G-JTT905-6 | G-JTT905-6 | G-JTT905-4 |
| 0x0B04→0x8001 | T1 | G-JTT905-6 | G-JTT905-6 | G-JTT905-4 |
| 下行命令→0x0001 | T6（形状） | G-JTT905-6 | G-JTT905-6 | G-JTT905-4 |

## 3. 依赖、状态和错误（D3）

依赖链为 `ip → jtt905`；raw planner 依赖 TCP 生成器提供三次握手、PSH 数据和四次挥手。自动流程是签到→中心应答→心跳×N→中心应答→签退→中心应答；每个 ISU 的 MsgSN 和平台应答 SN 独立，uint16 回绕。`0x8001` 是中心→ISU 的中心通用应答，`0x0001` 是 ISU→中心 的 ISU 通用应答；后者在 T6 中按实现缺省 `ReplyMsgId=0x8300`（文本下发引用），不代表当前生成器已实现 0x8300 下行消息。应答 Result=0 继续，业务失败/消息有误按协议流程结束或由显式 procedures 决定；配置错误（ISU 号、车牌、BCD 时间、Result 越界）由 ValidateConfig 返回错误，不产生成功输出、不重试。生成/写包失败终止任务；TCP 超时沿用 TCP 层超时策略。

## 4. 性能设计与验收（D4）

配置和消息按 generator 流式展开，不聚合全会话；队列沿引擎有界队列，单流新增内存为当前 PacketConfig 和载荷大小；并行度由 packet worker 配置决定。基线为 1 流、12 帧，目标为有限 flows 批量，压力/长时/并发/背压边界尚无实测承诺，列 G-JTT905-7。pcap 验收：MCP 建任务→落盘→tshark/字节脚本核对端口、帧序、MsgId、SN、长度、XOR、转义；NIC 验收：指定网卡 tcpdump 后按同一断言核对吞吐、间隔、丢包。未复跑不得写通过数字。

## 5. 八要素（D5）

- 文件：`internal/protocol/jtt905`、层注册/转换入口、`cases/jtt905.json`；本轮文档只登记，不改代码。
- 接口：严格层链 `spec_json.layers`；jtt905 终结层承载业务配置。当前 13 例均未声明 `flow_control`，数量由默认单流语义承载；多流数量必须另以 `flow_control` 表达并补例。
- 数据结构：ip 地址层、jtt905 业务层、procedures 有序数组；每个过程含 type 与可选应答字段。
- 主流程：Validate→规划 TCP 握手→按 procedure 生成应用帧→挥手→collector/writer。
- 错误：T10–T13 锚词拒绝；错误不落成功 pcap。
- 性能边界：有界队列、流式 payload；压力六档与 NIC 证据待 G-JTT905-7。
- 冲突点：旧扁平字段、旧 0x1001/0x1002 文档、把 JTT905 当 JT809 CRC 族，均不得恢复。
- 回滚：移除本轮三文件新增内容即可；不恢复旧合集拆分声明或旧扁平案例。

## 6. 动态字段清单（D6）

| 字段 | 策略 | 序号/边界 | 代码位置或缺口 |
|---|---|---|---|
| `ip.src`/`ip.dst` | fixed；inc/rand/list/pattern 需策略入口 | 按 flow 序号，rand 使用 seed+i，越界回绕 | 层链动态通用入口；JTT905 多流例 G-JTT905-7 |
| TCP 源/目的端口 | raw 默认目的 10700；显式端口由承载层语义 | 源端口按流避免碰撞 | mapToFlowSpec/raw planner；逐策略动态待核 |
| `isu_id` | fixed；不宣称自动变化 | 每 ISU 独立，必须 12 位数字 | ValidateConfig；多 ISU 缺口 G-JTT905-7 |
| `initial_sn` | fixed | uint16，65535→0 回绕 | planner SN 状态；边界例 G-JTT905-3 |
| `platform_initial_sn` | fixed | 每 ISU 独立计数器 | planner 应答状态；T4 |
| `heartbeat_count`/interval | fixed | count≥0、interval≥0；0 为边界 | planner；多心跳/间隔 G-JTT905-3 |
| 业务体字符串、时间、位置 | fixed | 长度/BCD/范围校验 | jtt905 builder；T3/T5/T9，扩展字段缺口 |

`flows=N` 且没有任何动态字段时必须拒绝或告警，不能静默复制相同四元组；本轮 JSON 未宣称动态覆盖。

## 8. 缺口登记（D8）

- `G-JTT905-1`：41 个标准消息型未编排；迁入计划：先补终结层字段表和 procedure 类型，再补 cases 与 pcap。
- `G-JTT905-2`：7D01 独立 wire 例缺；迁入计划：补含 0x7D 的业务体并以 pcap 校准。
- `G-JTT905-3`：多心跳、实际间隔、SN 65535 回绕缺；迁入计划：补 heartbeat_count=3/5、interval、回绕矩阵。
- `G-JTT905-4`：Result=3 不属于当前代码/用例允许的 0/1/2 枚举；若规范或现网要求 Result=3，迁入计划：先以 JT/T 原文和实际平台行为裁定，再同步设计、代码、cases。
- `G-JTT905-5`：IPv6 缺；迁入计划：补 `[ipv6,jtt905]` 对称例并实测。
- `G-JTT905-6`：非正常应答后的状态机缺；迁入计划：Result 1/2/3 真实事件序列与终止断言。
- `G-JTT905-7`：多 ISU、动态整格、压力/NIC 验收缺；迁入计划：先补 flows 与动态字段实现，再补端到端例。
