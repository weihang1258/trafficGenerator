03过程中修复的存量问题

严重ftp 下载方向反了

"服务器发文件给客户端"的场景，抓包发现数据是客户端发给服务器的——方向被锚死在模式上。已修，修后严格断言数据通道 s2c 载荷指纹 == 文件指纹。

严重tftp 双填静默截断

同时配文件源和填充模板时，块数按模板算、内容按文件切——两套判断顺序打架，613 字节的文件只发 512 字节，无声无息。已修：文件源在两个维度统一优先。

严重rtmp 调试残留可致崩溃

开发期调试打印漏删，无数据的 rtmp 配置会触发数组越界。已删，并补守卫测试（复审代理对抗验证：把问题代码还原，测试必红）。

中等删除的文件还能用 / 双填结果随机

缓存不撒手：删掉的文件再引用仍出旧内容；同时填文件路径和文件 ID 时胜者漂移。已修：删除即失效，双填固定"文件路径优先"，契约写进接口描述。

中等socks5 / shadowsocks / imap 假拒绝或静默丢弃

三者以"链路径不可用"为由拒绝或降级文件引用——该前提被 8 个同行协议实证推翻。全部撤除并接线，悬空引用统一走"警告+跳过"。

05客户端复测指引
